## 1. 研究の背景と目的

### 1.1 着想の経緯

本研究は、**開発チームのメンバー自身が聴覚障害の当事者**であり、幼少期に発音の習得へ
とても苦戦した経験から着想を得たものである。「発音に不安を抱えている人の悩みを
少しでも減らしたい」という動機が出発点にある。

想定する利用者は、聴覚に障害のある人に限らず、**日本語らしい発音が難しい外国人**、
**中途失聴・難聴の人**など、発音に不安を抱えている人全般である。
本研究ではそのうち、最も切実な課題を抱える層として**聴覚特別支援学校の生徒**を
対象に検証を行う。

### 1.2 背景

聴覚に障害のある人は、自分の発した声を聴いて確認すること（聴覚フィードバック）が困難であり、
発音の練習において「自分の発音が手本とどう違うのか」を自ら把握しにくいという課題がある。
従来の指導では、指導者が対面で口の形を示し、触覚や視覚で伝える方法が採られてきたが、
指導者が常に隣にいる必要があり、自主的な反復練習が難しい。

近年の音声処理技術により、発音のピッチ（音の高低）・音の長さ・母音の質を数値化することは
可能になっている。しかし、聴覚障害のある人にとっては、**声だけを評価しても
「どう直せばよいか」が分からない**という問題が残る。

### 1.3 本研究の着眼点

本研究では、声（音声）と口の動き（映像）の**両方**を同時に扱う。とくに、

- 口の形は正しいが、声を出すタイミングがずれている
- 声のタイミングは合っているが、口の開き方が不足している

といった、**片方の情報だけでは検出できないずれ**を可視化することを重視した。
これは、聴覚フィードバックが得にくい状況で、視覚的な手がかりを補うという考え方に基づく。

### 1.4 アプリケーションが目指すもの

| 区分 | 内容 |
|------|------|
| **目的** | 発音に不安を抱えている人に、「声（口）のかたちを綺麗にする一歩を踏める」という嬉しさを届ける |
| **目標** | ユーザーが正しい発音をするための**最適な解決策をアプリ内で提案する**こと |
| **工夫** | スマートフォン等で撮影した映像と音声を解析し、お手本と比較して改善点を表示したうえで、次に取り組むべき練習を提案する |

### 1.5 本調査の目的

上記のアプリケーションを聴覚特別支援学校の生徒に一定期間使用してもらい、
以下の2点を検討する。

1. **有効性の検討**：継続使用により、アプリが算出する発音スコアがどのように推移するか
2. **受容性の検討**：実際の教育現場で、生徒が無理なく継続して使用できるか

## 2. アプリケーションの概要（コンセプト）

### 2.1 名称とコンセプト

**SP-PS（Speech Practice - Pronunciation Support）**

> 「声（口）のかたちを綺麗にする一歩を踏める嬉しさを届ける」

自分の発音を、**耳ではなく目で確認できる**ようにすることを中心に据えた
Web ベースの発音練習アプリケーションである。

### 2.2 設計上の基本方針

| 方針 | 内容 |
|------|------|
| 視覚中心のフィードバック | 音を聴かなくても理解できるよう、スコア・グラフ・口の形の図で提示する |
| お手本は実在の指導者 | 合成音声ではなく、指導者が実際に発音した音声と映像を手本として用いる |
| 声と口の両面から評価 | 音声解析と映像解析を組み合わせ、片方だけでは分からないずれを検出する |
| **解決策を提案する** | 「点数が低い」で終わらせず、**次に何をどう直せばよいか**を具体的に提示する（本アプリの目標そのもの） |
| 自主練習の支援 | 練習履歴から苦手な音を自動抽出し、次に何を練習すべきかを提示する |

### 2.3 利用の流れ

```
① お手本を提供する人が単語を登録する
     単語のテキスト（表記・読み）＋ 発音している様子を3秒間録画
     → この録画から「お手本の音声」と「お手本の口の動き」を取り込む
     ※ アプリの一般的な想定は家族。本調査では担当教員を想定（§4.5）

② 生徒が練習する
     お手本を見る・聴く（口の動きの動画、音の高低のグラフ）
       ↓
     録音・録画する（画面のカウントダウンとガイド表示に合わせて発音）
       ↓
     結果を確認する（点数、どの音がずれていたか、口の開き方の過不足）

③ 記録を振り返る
     練習ごとの点数が自動的に記録され、推移をグラフで確認できる
```

### 2.4 聴覚障害のある利用者への配慮（実装済み）

| 機能 | 目的 |
|------|------|
| 録音タイミングガイド | 発音のタイミングを、音ではなく画面の表示で伝える。録音開始前に「3・2・1」を大きく表示し、録音中はお手本のテンポに合わせて発音すべき文字が順に光る |
| 口の形の可視化 | 母音ごとの口の形を、イラストと指導者の実写映像の両方で確認できる |
| 音の高低のグラフ表示 | 聴き取れない音の高低の変化を、線グラフとして視覚的に提示する |
| 文字による結果提示 | 「口の開きが足りない」等、改善点を文章で提示する |

### 2.5 提案される「解決策」の内容

本アプリの目標は解決策の提案にある。実装済みの提案機能は以下のとおり。

| 提案 | 内容 | 表示場所 |
|------|------|---------|
| **次はこれだけ直そう** | その回の結果から、最も改善効果の高い1点に絞って提示する（例：「『あ』の長さ（リズム）がお手本とちがいます」） | 結果画面 |
| 口の形の具体的な指摘 | 音ごとに「口の開きが足りない」「開きすぎ」を判定して示す | 結果画面 |
| 類似単語の提案 | 同じアクセント型で練習回数が少ない単語を次の練習候補として示す | 結果画面 |
| 今日のレッスン | 練習履歴から、その日に取り組むメニュー（復習・苦手音・口の形・挑戦）を自動編成する | ホーム画面 |
| 苦手音の集中ドリル | 繰り返しスコアが低い音を特定し、「音単独 → 音節 → 語頭 → 語中・語尾 → 単語」の順に練習させる | 集中ドリル画面 |

一度に多くを指摘すると負担になるため、**結果画面では改善点を1つに絞って提示**する設計としている。

## 3. アプリケーションの仕様

### 3.1 システム構成

Web アプリケーションとして実装されており、利用者は端末のブラウザからアクセスする。
**専用アプリのインストールは不要**である。

```
┌─────────────────────┐        ┌──────────────────────────┐
│ 利用者の端末          │        │ サーバー                   │
│（ブラウザ）           │        │（Python / Flask）          │
│                     │        │                          │
│ ・カメラで撮影        │ ──────▶ │ ・音声解析                 │
│ ・マイクで録音        │  録音   │ ・映像解析                 │
│ ・結果の表示          │ ◀────── │ ・点数の算出               │
└─────────────────────┘  結果   └──────────────────────────┘
```

処理の重い解析はすべてサーバー側で行い、端末側は撮影と表示のみを担当する。

### 3.2 主要な技術要素

| 要素 | 使用技術 | 役割 |
|------|---------|------|
| 音素の時刻特定 | Julius（音声認識エンジン） | 「どの音を、いつ発音したか」を音声から特定する |
| 音の高低の抽出 | Praat / parselmouth | 声の高さの変化を数値化する |
| 母音の質の評価 | フォルマント分析 | 母音の音色を数値化する |
| 口の形の検出 | MediaPipe FaceMesh | 映像から唇の位置を検出し、口の開き具合を数値化する |
| 声と口の照合 | DTW（動的時間伸縮法） | 声と口の動きのタイミングのずれを算出する |

> **補足：** MediaPipe は映像から顔の特徴点（座標）を取り出す処理であり、
> 個人を識別・照合する機能は使用していない。

### 3.3 評価項目

発音の点数は、以下の3項目の合計（100点満点）で算出する。

| 項目 | 配点 | 内容 |
|------|------|------|
| アクセント | 50点 | 音の高低のパターンが手本とどれだけ一致しているか |
| 音の長さ | 30点 | 各音の長さの配分が手本とどれだけ一致しているか |
| 母音の質 | 20点 | 母音の音色が手本とどれだけ近いか |

これとは別に、**点数には反映しない**参考情報として以下を表示する。

- 口の開き具合の過不足（音ごと）
- 声と口の動きのタイミングのずれ（ミリ秒単位）
- 声の音色の類似度

### 3.4 利用環境

| 項目 | 要件 |
|------|------|
| 端末 | カメラとマイクを備えた**スマートフォン**・タブレット・PC（スマートフォンでの利用を主に想定） |
| ブラウザ | Google Chrome / Microsoft Edge（カメラ機能に対応したもの） |
| ネットワーク | 運用形態により異なる（§4.4 参照） |
| 1回の練習所要時間 | 約1〜2分（お手本確認・録音・結果確認を含む） |

## 4. 調査計画

### 4.1 調査の目的

| 検討事項 | 確認する内容 | 用いるデータ |
|---------|------------|------------|
| 有効性 | 1か月間の継続使用により、発音スコアがどのように推移するか | アプリのスコア記録 |
| 受容性・アプリの評価 | 生徒が無理なく継続して使用できるか、使いやすいと感じたか | 利用状況の記録＋**使用後アンケート**（自由記述のフィードバックを含む） |

### 4.2 対象者

| 項目 | 内容 |
|------|------|
| 対象 | 聴覚特別支援学校に在籍する児童・生徒（小学部・中学部・高等部） |
| 人数 | （記入：〇名程度） |
| 選定方法 | 学校側と協議のうえ、担当教員が発音練習に取り組んでいる生徒に対して募集する |
| 除外基準 | 本人または保護者の同意が得られない場合 / 体調等により参加が困難な場合 |

**参加者には未成年者が含まれるため、保護者の同意と本人のアセント（年齢に応じた説明と同意）
の両方を取得する**（§7.1 参照）。

また、参加者の**学年および聴覚障害の程度**を事前に取得する。聴覚障害の程度は
**要配慮個人情報**に該当するため、取得にあたっては §5.2 の要件を満たす必要がある。

### 4.3 調査期間

| 段階 | 期間 | 内容 |
|------|------|------|
| 事前説明・同意取得 | 開始前 | 生徒・保護者・担当教員への説明と同意取得 |
| 事前準備 | 開始前 | 練習する単語の登録（指導者による手本の録画） |
| 使用期間 | **約1か月** | 生徒が自主的または授業内でアプリを使用する |
| 事後 | 終了後 | データの集計・分析 |

使用の頻度・時間は強制せず、学校の指導計画の範囲内で自由に使用してもらう。

### 4.4 運用形態

> **【要確定】** 本項目は指導教員および学校側と協議のうえ決定する。
> データの保管場所が変わるため、審査申請前に確定が必要である。

| 案 | 構成 | データの保管場所 | 特徴 |
|----|------|---------------|------|
| **A. 端末内で完結** | 学校の PC 各台にインストールし、単独で動作させる | その PC 内のみ（外部送信なし） | 外部にデータが出ないため、個人情報保護の観点で最も説明が容易。ただし台数分の設定作業が必要 |
| **B. 校内サーバー方式** | 学校内の PC 1台をサーバーとし、校内ネットワークの端末から利用する | 校内サーバー1台のみ（外部送信なし） | 複数端末から利用でき、データも1か所に集約できる。校内ネットワークの利用許可が必要 |
| **C. クラウド方式** | インターネット上のサーバー（Railway 社のサービス）に設置する | **国外のデータセンター** | 場所を選ばず利用できるが、国外へのデータ送信について審査で説明が必要 |

**推奨：** 音声と映像を扱う性質上、データが外部に出ない **案 A または案 B** を推奨する。

### 4.5 実施体制

| 役割 | 担当 | 業務 |
|------|------|------|
| 研究責任者 | （指導教員名） | 研究全体の統括・倫理的配慮の監督 |
| 研究実施者 | （学生名） | アプリの開発・保守、データの集計と分析 |
| 現場担当 | 学校の担当教員 | 生徒への説明、練習の実施、単語の登録 |
| お手本の提供者 | 担当教員（想定） | 練習する単語を発音し、録画する |

> **お手本提供者について：** アプリの一般的な利用では家族がお手本を務めることを想定しているが、
> 本調査では**担当教員がお手本を提供する**ことを想定している。
> お手本の音声・映像は保存され、参加者が繰り返し再生するため、
> **提供者本人からも書面で同意を得る**（§7.1）。
> 仮に家族に依頼する場合も、同様に同意を得たうえで実施する。

### 5.2 要配慮個人情報の取扱い（聴覚障害の程度）

> **本項目は審査上の最重要事項である。**

個人情報保護法において、**心身の機能の障害に関する情報は「要配慮個人情報」**に該当する。
本研究では聴覚障害の程度を収集するため、以下の取扱いを行う。

#### 取得の必要性（研究上の根拠）

聴覚障害の程度は、発音の状態および練習による変化に影響しうる要因である。
本アプリが「どの程度の聴覚障害のある生徒に有効か」を検討するうえで必要な情報であり、
**研究目的の達成に不可欠**であるため取得する。

#### 取得にあたっての要件

| 要件 | 対応 |
|------|------|
| 本人の同意 | 要配慮個人情報の取得には**本人（および未成年の場合は保護者）の明示的な同意が必須**である。説明文書に「聴覚障害の程度を取得すること」を明記し、他の項目と区別して同意欄を設ける |
| 取得項目の限定 | 研究目的に必要な最小限の項目のみとする（下表） |
| 取得経路 | 生徒本人に直接尋ねる形は取らず、**学校が保有する情報から担当教員を通じて提供を受ける**形とする |
| 第三者提供 | 一切行わない |

#### 取得する項目 <span>【要確定】</span>

以下は案である。学校側と協議し、**必要最小限**に絞ること。

| 項目 | 取得の要否 | 備考 |
|------|-----------|------|
| 聴力レベル（dB）または障害等級 | 要検討 | 詳細な数値ほど再識別リスクが高まる。区分（例：高度・重度の2分類）に丸めることを推奨 |
| 補聴器・人工内耳の使用有無 | 要検討 | 発音への影響が大きく、研究上の意義は高い |
| 診断名・発症時期・原因 | **取得しない** | 研究目的に不要であり、機微性が高い |

### 5.3 再識別リスクと対策

> **審査で必ず問われる論点である。**

聴覚特別支援学校は在籍者数が少なく、**「学校名 ＋ 学年 ＋ 聴覚障害の程度」の3つが揃うと、
個人が特定されうる**（例：「A校 中学部2年で重度難聴の生徒」が1名しかいない場合）。
氏名を収集しなくても、属性の組み合わせによって個人が identify されうる点に注意が必要である。

#### 対策

| 対策 | 内容 |
|------|------|
| 障害の程度を区分に丸める | 詳細な聴力レベル（dB 値）ではなく、2〜3区分に集約して保持する |
| 学年を学部単位に丸める | 分析上支障がなければ「中学部2年」ではなく「中学部」として扱う |
| 公表時の配慮 | 学年と障害の程度を組み合わせた事例提示（「中学部2年・重度難聴の生徒Aは…」等）を行わない |
| 学校名の匿名化 | 公表時は学校名を伏せる（学校側の意向を確認のうえ判断） |
| 少数セルの非公表 | 集計時、該当者が数名以下となる区分は単独で公表しない |

### 5.4 収集しないデータ

以下は**一切保存しない**。これはアプリの設計上そうなっており、研究のために変更もしない。

| 項目 | 現在の扱い |
|------|-----------|
| **生徒の音声（録音データ）** | 解析のために一時的に使用したのち、次の録音時に上書きされる。蓄積されない |
| **生徒の顔・口元の映像** | 解析が終わった時点で**プログラムが自動的に削除**する |
| 氏名・連絡先等 | アプリに入力する項目が存在しない |
| 診断名・発症時期等 | 取得しない（§5.2 参照） |

> **設計上の裏付け：** 生徒の録画ファイルは解析処理の直後にプログラムが削除する実装に
> なっており、録音音声は固定の一時ファイルに保存され毎回上書きされる。
> したがって、**過去の音声・映像は端末上にもサーバー上にも残らない**。

なお、**指導者が登録するお手本の音声・映像は保存される**。これは練習の手本として繰り返し
再生する必要があるためである。お手本を提供する指導者からは、別途同意を得る。

### 5.5 アンケートの実施

使用期間終了後、アプリの評価を目的としたアンケートを実施する。

| 項目 | 内容 |
|------|------|
| 実施時期 | 使用期間（約1か月）の終了後 |
| 所要時間 | 5〜10分程度 |
| 形式 | 選択式の設問＋自由記述欄 |
| 内容 <span>【要確定】</span> | 使いやすさ／続けやすさ／画面の分かりやすさ／今後も使いたいか／改善要望（自由記述） |
| 配慮 | 聴覚障害のある生徒が対象であるため、**文字と図を中心とした平易な設問**とする。学年・発達段階に応じて表現を調整する |
| 任意性 | 回答は任意であり、無回答による不利益はない |

自由記述で得られたフィードバックは、アプリの改善に活用する。
公表時は、個人が特定されうる記述（氏名・学校名・固有の出来事等）を除いたうえで引用する。

### 5.6 分析の方法

| 分析 | 内容 |
|------|------|
| スコアの推移 | 参加者ごとに、練習回数に対する得点の変化を回帰分析により評価する |
| 苦手な音の変化 | 音ごとの点数を集計し、初期に低かった音が改善したかを確認する |
| 利用状況 | 練習回数・継続日数を集計し、無理なく使用できたかを検討する |
| 属性との関連 | 学年・障害の程度とスコアの推移との関連を検討する（§5.3 の配慮のうえ実施） |
| アンケートの集計 | 選択式は単純集計、自由記述は内容ごとに分類して整理する |

個人が特定される形での公表は行わず、**集団としての傾向**、または匿名化した個別の推移として
報告する。

## 6. 個人情報およびデータの取扱い

### 6.1 参加者の識別方法と匿名化

参加者はアプリに**利用者 ID とパスワードでログイン**し、練習記録を個人ごとに分離して
保存する。ID とパスワードは**参加者本人が設定**する方針である。

#### 匿名性を確保するための運用ルール

本人が ID を自由に決められる場合、氏名やあだ名をそのまま入力してしまい、
**データ内に個人が識別できる文字列が残る**おそれがある。これを防ぐため、以下を徹底する。

| ルール | 内容 |
|--------|------|
| ID の形式を指定する | 研究者があらかじめ**参加者番号（例：A01, A02）を割り当て、これを ID とする**。本人が自由入力できる形にしない |
| 本人が決めるのはパスワードのみ | 「自分のアカウント」という感覚を持てるようにしつつ、識別子には個人情報が混入しない |
| 氏名等の入力を禁止 | 画面上に「名前は入れないでください」と明示し、入力欄にも注意書きを表示する |

> **推奨：** ID まで本人に決めさせると匿名化が崩れるリスクが高い。
> **ID は割り当て、パスワードのみ本人が設定する方式**を推奨する。
> ただし、小学部の児童にはパスワード管理自体が負担となりうるため、
> 低学年については担当教員が管理する等の配慮を検討する。

#### 対応表の管理

- 氏名と参加者番号（ID）の対応表は、**学校の担当教員が保管**し、研究者側には渡さない
  （または、施錠可能な場所に保管し、研究責任者のみが管理する）
- 研究者が取り扱うデータには氏名等の直接的な識別情報を含めない
- パスワードは**暗号化（ハッシュ化）して保存**し、平文では保持しない

> **【要確定】** 対応表の管理者・保管方法、および低学年のパスワード運用は
> 学校側と協議のうえ決定する。

### 6.2 データの保管と管理

| 項目 | 内容 |
|------|------|
| 保管場所 | §4.4 で決定した運用形態に準じる |
| アクセス制限 | データを保管する端末にはパスワードを設定し、研究関係者以外がアクセスできないようにする |
| 持ち出し | データを外部記憶媒体で持ち出す場合は、暗号化のうえ研究室内でのみ取り扱う |
| 通信 | ネットワーク経由で利用する場合は暗号化通信（HTTPS）を用いる |

### 6.3 保存期間と廃棄

| データ | 保存期間 | 廃棄方法 |
|--------|---------|---------|
| 研究データ（スコア等） | 研究終了後〇年間（大学規程に従う） | 電子データを完全に削除する |
| 学年・聴覚障害の程度 | 研究終了後〇年間（大学規程に従う） | 電子データを完全に削除する |
| アンケート回答・自由記述 | 研究終了後〇年間（大学規程に従う） | 電子データを完全に削除する／紙媒体は裁断 |
| 氏名と参加者番号の対応表 | 研究終了時点で速やかに廃棄 | 紙媒体は裁断、電子データは完全に削除 |
| お手本の音声・映像 | 調査終了後、速やかに削除 | 電子データを完全に削除する |

> **【要確定】** 保存期間は大学の研究倫理規程に定められた年数に合わせる。

## 7. 倫理的配慮

### 7.1 同意の取得

参加者に未成年者が含まれるため、**二重の同意手続き**を行う。

| 対象 | 手続き | 方法 |
|------|-------|------|
| 保護者 | インフォームド・コンセント | 説明文書を配布し、書面で同意を得る |
| 本人 | アセント（年齢に応じた説明と同意） | 平易な言葉と図を用いた説明文書を用い、本人の意思を確認する |
| 学校 | 実施の承諾 | 管理職・担当教員への説明と承諾の取得 |
| **お手本の提供者** | 音声・映像の使用についての同意 | 録画したお手本が保存され、参加者に繰り返し再生されること、調査終了後に削除することを説明し、書面で同意を得る |

**要配慮個人情報についての同意（重要）**

聴覚障害の程度は要配慮個人情報に該当するため、**研究参加そのものへの同意とは別に、
独立した同意欄を設ける**。同意書には以下を明記する。

- 聴覚障害の程度を取得すること、およびその具体的な項目
- 取得する理由（発音の変化との関連を検討するため）
- 第三者に提供しないこと
- **この項目に同意しなくても研究には参加できる**こと（可能な場合）

**本人への説明にあたっての配慮：**
- 聴覚障害のある生徒が対象であるため、**文字と図を中心とした説明資料**を用いる
- 必要に応じて手話通訳、または担当教員による補足説明を依頼する
- 年齢・発達段階に応じて説明資料の表現を調整する

### 7.2 参加の任意性と撤回の自由

- 参加は完全に任意であり、**参加しないことによる不利益は一切ない**ことを明記する
- 学業成績や学校での評価に一切影響しないことを、生徒と保護者の双方に明確に伝える
- **調査開始後であっても、理由を問わずいつでも中止できる**
- 中止を申し出た場合、その参加者のデータは速やかに削除する（ただし、既に集計・公表された
  分については削除できない旨をあらかじめ説明する）

### 7.3 予測される負担・リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| **心理的負担** | 発音を点数化されることで自信を失う、劣等感を抱く可能性がある | ・点数だけでなく改善点を具体的に示す設計にしている<br>・「前回より上がった点」を強調する表示にしている<br>・担当教員が生徒の様子に配慮し、負担が見られる場合は使用を中止する |
| **身体的負担** | 画面を見続けることによる疲労 | ・1回の練習は1〜2分程度<br>・使用頻度を強制せず、学校の指導計画の範囲内とする |
| **プライバシー** | 音声・映像は個人が特定されうる情報である | ・**生徒の音声・映像は保存しない設計**（§5.4）<br>・アプリに保存されるのはスコアと日時のみ |
| **時間的負担** | 授業時間や自習時間を使用する | ・学校の指導計画に組み込む形とし、追加の負担を生じさせない<br>・アンケートは5〜10分程度、1回のみ |
| **属性情報による特定** | 学校・学年・障害の程度の組み合わせから個人が推測されうる | ・障害の程度を区分に丸める<br>・少数事例を単独で公表しない<br>・詳細は §5.3 |
| **自由記述による特定** | フィードバックの記述内容から個人が推測されうる | ・引用時は固有名詞・個別の出来事を削除する<br>・必要に応じて要約して引用する |

### 7.4 参加者にとっての利益

- 自分の発音の状態を、聴覚に頼らず**視覚的に確認**できる
- 指導者が隣にいない場面でも、自分のペースで反復練習ができる
- 練習の記録が蓄積され、自分の変化を確認できる

ただし、**本アプリの使用により発音が改善することは保証されない**ことを、
説明文書に明記する。

### 7.5 結果の公表

- 研究成果は卒業研究および学会等で発表する可能性がある
- 公表にあたっては個人が特定されない形とする
- **学校名についても、学校側の意向を確認したうえで匿名化の要否を判断する**

## 8. 調査開始までに確定・実装が必要な事項

> 本節は、**審査申請前に解決すべき課題**の一覧である。

### 8.1 確定が必要な事項（協議事項）

| # | 項目 | 内容 |
|---|------|------|
| 1 | **運用形態** | §4.4 の案A/B/Cのいずれにするか。データの保管場所が決まらないと申請書が書けない |
| 2 | 参加人数 | 対象となる児童・生徒の人数 |
| 3 | 対応表の管理者 | 氏名と参加者番号の対応表を誰がどう保管するか |
| 4 | データ保存期間 | 大学の研究倫理規程に定められた年数 |
| 5 | 練習対象の単語 | どの単語を登録するか（学校の指導内容に合わせる） |
| 6 | お手本の話者 | 誰が手本を録画するか（担当教員を想定）とその同意 |
| 7 | **障害の程度の取得項目** | 聴力レベルをどの粒度で取得するか（§5.2）。必要最小限に絞る |
| 8 | **ID の付与方式** | 参加者番号を割り当てるか、本人に決めさせるか（§6.1・匿名性に直結） |
| 9 | 低学年のパスワード運用 | 小学部の児童が自力で管理できない場合の代替手段 |
| 10 | アンケートの設問 | 具体的な設問文（§5.5）。平易な表現・図の併用を前提に作成する |

### 8.2 実装が必要な事項（技術的課題）

現在のアプリは**1人で使用する前提**で作られているため、複数名で使用するには以下の実装が必要である。

| # | 課題 | 現状 | 必要な対応 |
|---|------|------|-----------|
| 1 | **利用者の識別ができない** | 利用者を区別する仕組みが一切なく、全員の練習記録が1つのファイルに混在してしまう | **ログイン機能を実装する**（下記の要件を満たすこと） |
| 2 | **記録が500件で打ち切られる** | 保存件数の上限が500件で、それを超えると古い記録から自動的に削除される | 上限を引き上げる、または参加者ごとに保存する |
| 3 | 誤操作による他者データの変更 | 単語の削除・編集が誰でも実行できる | 管理機能を教員のみが使えるよう保護する |

> **注意：** 課題1が未解決のまま調査を開始すると、**誰のデータか区別できず、
> 研究データとして使用できない**。調査開始前に必ず実装する必要がある。

#### ログイン機能に求められる要件

| # | 要件 | 理由 |
|---|------|------|
| 1 | 利用者ごとに練習記録を分離して保存する | 個人ごとの推移を分析するため |
| 2 | パスワードは平文で保存せず、ハッシュ化する | 参加者が他サービスと同じパスワードを使い回した場合の被害を防ぐため |
| 3 | ID に氏名等が入力されないようにする | 匿名性を確保するため（§6.1） |
| 4 | 他の参加者の記録を閲覧・変更できないようにする | 参加者間のプライバシーを守るため |
| 5 | 学年・障害の程度はアプリに入力させない | 要配慮個人情報をアプリ側に持たせず、研究者側で別管理するため |

> **設計方針：** 学年・聴覚障害の程度は**アプリには保存せず**、研究者が別途管理する
> 名簿（参加者番号と属性の対応表）で保持することを推奨する。
> こうすることで、アプリ本体が要配慮個人情報を扱わない構成にできる。

## 9. 研究の限界

申請書および結果の解釈にあたって、以下の限界を認識しておく必要がある。

| 限界 | 内容 |
|------|------|
| **評価指標の妥当性** | 「発音が良くなった」の判断を、アプリが算出するスコアのみに依拠している。このスコアは本研究で開発した独自の指標であり、外部の基準（専門家による評価等）との一致は未検証である |
| **主観評価の偏り** | アンケートは使用後1回のみであり、回答時の印象に左右される。また、研究に協力しているという意識から肯定的な回答に偏る可能性がある（社会的望ましさバイアス） |
| **属性による層別分析の限界** | 学年・障害の程度による違いを検討するが、各層の人数が少ないため、統計的な比較は困難であり、傾向の記述に留まる |
| **対照群がない** | アプリを使用しない群との比較を行わないため、スコアの変化がアプリによるものか、通常の授業や成長によるものかを分離できない |
| **参加者数** | 対象が限られるため、統計的な一般化には限界がある |
| **お手本が1名** | 単語ごとに1名分の手本しかなく、その話者の発話特性の影響を受ける |

### 補足：さらに検討の余地がある事項

| 追加案 | 得られるもの | 負担 |
|--------|------------|------|
| 担当教員へのヒアリング | 教育現場から見た導入の現実性・改善点。生徒の主観評価では拾えない運用面の課題が把握できる | 小（教員1〜2名への聞き取り） |
| 使用期間の途中でのアンケート | 初期の戸惑いと慣れた後の評価を区別できる | 小（5分程度、追加1回） |

> **倫理審査は申請内容の変更に手続きを要するため、実施する可能性があるものは
> 最初の申請に含めておくことを推奨する。**
