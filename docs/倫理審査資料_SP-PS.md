## 1. 研究の背景と目的

### 1.1 着想の経緯

本研究は、**開発チームのメンバー自身が聴覚障害の当事者**であり、幼少期に発音の習得へ
とても苦戦した経験から着想を得たものである。「発音に不安を抱えている人の悩みを
少しでも減らしたい」という動機が出発点にある。

想定する利用者は、聴覚に障害のある人に限らず、**日本語らしい発音が難しい外国人**、
**中途失聴・難聴の人**など、発音に不安を抱えている人全般である。
本研究ではそのうち、最も切実な課題を抱える層として**聴覚特別支援学校の生徒**を
対象に検証を行う。

### 1.2 背景

聴覚に障害のある人は、自分の発した声を聴いて確認すること（聴覚フィードバック）が困難であり、
発音の練習において「自分の発音がお手本とどう違うのか」を自ら把握しにくいという課題がある。
従来の指導では、指導者が対面で口の形を示し、触覚や視覚で伝える方法が採られてきたが、
指導者が常に隣にいる必要があり、自主的な反復練習が難しい。

近年の音声処理技術により、発音のピッチ（音の高低）・音の長さ・母音の質を数値化することは
可能になっている。しかし、聴覚障害のある人にとっては、**声だけを評価しても
「どう直せばよいか」が分からない**という問題が残る。

### 1.3 本研究の着眼点

本研究では、声（音声）と口の動き（映像）の**両方**を同時に扱う。とくに、

- 口の形は正しいが、声を出すタイミングがずれている
- 声のタイミングは合っているが、口の開き方が不足している

といった、**片方の情報だけでは検出できないずれ**を可視化することを重視した。
これは、聴覚フィードバックが得にくい状況で、視覚的な手がかりを補うという考え方に基づく。

### 1.4 アプリケーションが目指すもの

| 区分 | 内容 |
|------|------|
| **目的** | 発音に不安を抱えている人に、「声（口）のかたちを綺麗にする一歩を踏める」という嬉しさを届ける |
| **目標** | ユーザーが正しい発音をするための**最適な解決策をアプリ内で提案する**こと |
| **工夫** | スマートフォン等で撮影した映像と音声を解析し、お手本と比較して改善点を表示したうえで、次に取り組むべき練習を提案する |

### 1.5 本調査の目的

上記のアプリケーションを聴覚特別支援学校の生徒に一定期間（約1か月）使用してもらい、
以下の**2点**を明らかにする。

| # | 目的 | 具体的に確認すること |
|---|------|-------------------|
| **①** | **発音の改善がみられるか** | このアプリを使用することで、実際に発音が改善するのかを検証する |
| **②** | **アプリへのフィードバックを得る** | 実際に使った生徒から評価と改善要望を集め、アプリの改善につなげる |

目的①は開発したアプリの**効果**を問うものであり、目的②はアプリを**より良くするため**の
情報収集である。いずれも、本アプリを実際の利用場面で検証する初めての機会となる。

## 2. アプリケーションの概要（コンセプト）

### 2.1 名称とコンセプト

**SP-PS（Speech Practice - Pronunciation Support）**

> 「声（口）のかたちを綺麗にする一歩を踏める嬉しさを届ける」

自分の発音を、**耳ではなく目で確認できる**ようにすることを中心に据えた
Web ベースの発音練習アプリケーションである。

### 2.2 設計上の基本方針

| 方針 | 内容 |
|------|------|
| 視覚中心のフィードバック | 音を聴かなくても理解できるよう、スコア・グラフ・口の形の図で提示する |
| お手本は実在の指導者 | 合成音声ではなく、指導者が実際に発音した音声と映像をお手本として用いる |
| 声と口の両面から評価 | 音声解析と映像解析を組み合わせ、片方だけでは分からないずれを検出する |
| **解決策を提案する** | 「点数が低い」で終わらせず、**次に何をどう直せばよいか**を具体的に提示する（本アプリの目標そのもの） |
| 自主練習の支援 | 練習履歴から苦手な音を自動抽出し、次に何を練習すべきかを提示する |

### 2.3 利用の流れ

```
① お手本を提供する人（保護者や家族、学校の先生など）が単語を登録する
     単語のテキスト（表記・読み）＋ 発音している様子を3秒間録画
     → この録画から「お手本の音声」と「お手本の口の動き」を取り込む
     ※ 家庭で使う場合は親などの家族を想定している。
       本調査では学校の担当教員がお手本を提供する。

② 生徒が練習する
     お手本を見る・聴く（口の動きの動画、音の高低のグラフ）
       ↓
     録音・録画する（画面のカウントダウンとガイド表示に合わせて発音）
       ↓
     結果を確認する（点数、どの音がずれていたか、口の開き方の過不足）

③ 記録を振り返る
     練習ごとの点数が自動的に記録され、推移をグラフで確認できる
```

### 2.4 聴覚障害のある利用者への配慮（実装済み）

| 機能 | 目的 |
|------|------|
| 録音タイミングガイド | 発音のタイミングを、音ではなく画面の表示で伝える。録音開始前に「3・2・1」を大きく表示し、録音中はお手本のテンポに合わせて発音すべき文字が順に光る |
| 口の形の可視化 | 母音ごとの口の形を、イラストと指導者の実写映像の両方で確認できる |
| 音の高低のグラフ表示 | 聴き取れない音の高低の変化を、線グラフとして視覚的に提示する |
| 文字による結果提示 | 「口の開きが足りない」等、改善点を文章で提示する |

### 2.5 提案される「解決策」の内容

本アプリの目標は解決策の提案にある。実装済みの提案機能は以下のとおり。

| 提案 | 内容 | 表示場所 |
|------|------|---------|
| **次はこれだけ直そう** | その回の結果から、最も改善効果の高い1点に絞って提示する（例：「『あ』の長さ（リズム）がお手本とちがいます」） | 結果画面 |
| 口の形の具体的な指摘 | 音ごとに「口の開きが足りない」「開きすぎ」を判定して示す | 結果画面 |
| 類似単語の提案 | 同じアクセント型で練習回数が少ない単語を次の練習候補として示す | 結果画面 |
| 今日のレッスン | 練習履歴から、その日に取り組むメニュー（復習・苦手音・口の形・挑戦）を自動編成する | ホーム画面 |
| 苦手音の集中ドリル | 繰り返しスコアが低い音を特定し、「音単独 → 音節 → 語頭 → 語中・語尾 → 単語」の順に練習させる | 集中ドリル画面 |

一度に多くを指摘すると負担になるため、**結果画面では改善点を1つに絞って提示**する設計としている。

## 3. アプリケーションの仕様

### 3.1 システム構成

Web アプリケーションとして実装されており、利用者は端末のブラウザからアクセスする。
**専用アプリのインストールは不要**である。

| | 利用者の端末（フロント） | サーバー（バックエンド） |
|---|---|---|
| 動作環境 | ブラウザ（スマートフォン等） | Python / Flask |
| 役割 | カメラで撮影・マイクで録音し、結果を表示する | 音声解析・映像解析を行い、点数を算出する |
| 負荷 | 軽い（撮影と表示のみ） | 重い処理はすべてこちらが担当 |

やり取りの流れは「端末で録音・録画 → サーバーへ送信 → サーバーで解析 → 結果を端末に返して表示」となる。

### 3.2 主要な技術要素

| 要素 | 使用技術 | 役割 |
|------|---------|------|
| 音素の時刻特定 | Julius（音声認識エンジン） | 「どの音を、いつ発音したか」を音声から特定する |
| 音の高低の抽出 | Praat / parselmouth | 声の高さの変化を数値化する |
| 母音の質の評価 | フォルマント分析 | 母音の音色を数値化する |
| 口の形の検出 | MediaPipe FaceMesh | 映像から唇の位置を検出し、口の開き具合を数値化する |
| 声と口の照合 | DTW（動的時間伸縮法） | 声と口の動きのタイミングのずれを算出する |

> **補足：** MediaPipe は映像から顔の特徴点（座標）を取り出す処理であり、
> 個人を識別・照合する機能は使用していない。

### 3.3 評価項目

発音の点数は、以下の3項目の合計（100点満点）で算出する。

| 項目 | 配点 | 内容 |
|------|------|------|
| アクセント | 50点 | 音の高低のパターンがお手本とどれだけ一致しているか |
| 音の長さ | 30点 | 各音の長さの配分がお手本とどれだけ一致しているか |
| 母音の質 | 20点 | 母音の音色がお手本とどれだけ近いか |

これとは別に、**点数には反映しない**参考情報として以下を表示する。

- 口の開き具合の過不足（音ごと）
- 声と口の動きのタイミングのずれ（ミリ秒単位）
- 声の音色の類似度

### 3.4 利用環境

| 項目 | 要件 |
|------|------|
| 端末 | カメラとマイクを備えた**スマートフォン**・タブレット・PC（スマートフォンでの利用を主に想定） |
| ブラウザ | Google Chrome / Microsoft Edge（カメラ機能に対応したもの） |
| ネットワーク | 運用形態により異なる（§4.4 参照） |
| 1回の練習所要時間 | 約1〜2分（お手本確認・録音・結果確認を含む） |

## 4. 調査計画

### 4.1 調査の目的

| # | 目的 | 確認する内容 | 用いるデータ |
|---|------|------------|------------|
| **①** | **発音の改善がみられるか** | 1か月間の継続使用により、発音スコアがどのように推移するか | アプリのスコア記録（練習ごとの得点・音ごとの得点） |
| **②** | **アプリへのフィードバック** | 使いやすかったか、続けやすかったか、どこを改善すべきか | **使用後アンケート**（選択式＋自由記述）／利用状況の記録 |

いずれの目的も、参加者に特別な課題を課すものではなく、**通常の発音練習をアプリで
行ってもらい、その記録と感想を収集する**という形式である。

### 4.2 対象者

| 項目 | 内容 |
|------|------|
| 対象 | 石川県立ろう学校に在籍する生徒（**中学部・高等部**） |
| 人数 | （記入：〇名程度） |
| 選定方法 | 学校側と協議のうえ、担当教員が発音練習に取り組んでいる生徒に対して募集する |
| 除外基準 | 本人または保護者の同意が得られない場合 / 体調等により参加が困難な場合 |

**参加者には未成年者が含まれるため、保護者の同意と本人のアセント（年齢に応じた説明と同意）
の両方を取得する**。

また、参加者の**学年および聴覚障害の程度**を事前に取得する。聴覚障害の程度は
**要配慮個人情報**に該当するため、取得にあたっては §5.2 のとおり取り扱う。

### 4.3 調査期間

| 段階 | 期間 | 内容 |
|------|------|------|
| 事前説明・同意取得 | 開始前 | 生徒・保護者・担当教員への説明と同意取得 |
| 事前準備 | 開始前 | 練習する単語の登録（指導者によるお手本の録画） |
| 使用期間 | **約1か月** | 生徒が自主的または授業内でアプリを使用する |
| 事後 | 終了後 | データの集計・分析 |

使用の頻度・時間は強制せず、学校の指導計画の範囲内で自由に使用してもらう。

### 4.4 運用形態

> **【要確定】** 本項目は指導教員および学校側と協議のうえ決定する。
> データの保管場所が変わるため、審査申請前に確定が必要である。

| 案 | 構成 | データの保管場所 | 特徴 |
|----|------|---------------|------|
| **A. 端末内で完結** | 学校の PC 各台にインストールし、単独で動作させる | その PC 内のみ（外部送信なし） | 外部にデータが出ないため、個人情報保護の観点で最も説明が容易。ただし台数分の設定作業が必要 |
| **B. 校内サーバー方式** | 学校内の PC 1台をサーバーとし、校内ネットワークの端末から利用する | 校内サーバー1台のみ（外部送信なし） | 複数端末から利用でき、データも1か所に集約できる。校内ネットワークの利用許可が必要 |
| **C. クラウド方式** | インターネット上のサーバー（Railway 社のサービス）に設置する | **国外のデータセンター** | 場所を選ばず利用できるが、国外へのデータ送信について審査で説明が必要 |

**推奨：** 音声と映像を扱う性質上、データが外部に出ない **案 A または案 B** を推奨する。

## 5. 収集するデータ

### 5.1 収集するデータの一覧

| # | データ項目 | 内容 | 区分 | 取得方法 |
|---|-----------|------|------|---------|
| 1 | 発音スコア | 総合点、アクセント・長さ・母音の各点数 | 通常 | アプリが自動記録 |
| 2 | 音ごとのスコア | 「あ」「か」など、音単位の点数 | 通常 | アプリが自動記録 |
| 3 | 練習日時 | 練習した日付と時刻 | 通常 | アプリが自動記録 |
| 4 | 練習した単語 | 単語の表記と読み | 通常 | アプリが自動記録 |
| 5 | 利用者 ID | 参加者がログインに用いる識別子 | 通常 | §6.1 の方式による |
| 6 | **学年** | 中学部・高等部の別および学年 | **属性情報** | 事前に調査票で取得 |
| 7 | **聴覚障害の程度** | 聴力レベル等 | **要配慮個人情報** | 事前に調査票で取得（学校を通じて） |
| 8 | アンケート回答 | 使いやすさ・継続意欲等（選択式） | 通常 | 使用期間終了後に実施 |
| 9 | 自由記述フィードバック | 改善要望・感想等 | 通常 | アンケート内で取得 |

**アプリが自動記録する内容の例（1回の練習分）：**

```json

  "練習日時":   "2026-09-15T10:23:45",
  "単語":       "温度（おんど）",
  "総合点":     72,
  "アクセント": 36.5,
  "長さ":       21.0,
  "母音":       14.5,
  "音ごとの点数": [
    { "音": "お", "点数": 68 },
    { "音": "ん", "点数": 75 },
    { "音": "ど", "点数": 73 }
  ]
}
```

### 5.2 要配慮個人情報の取扱い（聴覚障害の程度）

> **本項目は審査上の最重要事項である。**

個人情報保護法において、**心身の機能の障害に関する情報は「要配慮個人情報」**に該当する。
本研究では聴覚障害の程度を収集するため、以下の取扱いを行う。

#### 取得の必要性（研究上の根拠）

聴覚障害の程度は、発音の状態および練習による変化に影響しうる要因である。
本アプリが「どの程度の聴覚障害のある生徒に有効か」を検討するうえで必要な情報であり、
**研究目的の達成に不可欠**であるため取得する。

### 5.3 再識別リスクと対策

聴覚特別支援学校は在籍者数が少なく、**「学校名 ＋ 学年 ＋ 聴覚障害の程度」の3つが揃うと、
個人が特定されうる**（例：「A校 中学部2年で重度難聴の生徒」が1名しかいない場合）。
氏名を収集しなくても、属性の組み合わせによって個人が識別されうる点に注意が必要である。

#### 対策

| 対策 | 内容 |
|------|------|
| 障害の程度を区分に丸める | 詳細な聴力レベル（dB 値）ではなく、2〜3区分に集約して保持する |
| 学年を学部単位に丸める | 分析上支障がなければ「中学部2年」ではなく「中学部」として扱う |
| 公表時の配慮 | 学年と障害の程度を組み合わせた事例提示（「中学部2年・重度難聴の生徒Aは…」等）を行わない |
| 学校名の匿名化 | 公表時は学校名を伏せる（学校側の意向を確認のうえ判断） |
| 少数セルの非公表 | 集計時、該当者が数名以下となる区分は単独で公表しない |

### 5.4 収集しないデータ

以下は**一切保存しない**。これはアプリの設計上そうなっており、研究のために変更もしない。

| 項目 | 現在の扱い |
|------|-----------|
| **生徒の音声（録音データ）** | 解析のために一時的に使用したのち、次の録音時に上書きされる。蓄積されない |
| **生徒の顔・口元の映像** | 解析が終わった時点で**プログラムが自動的に削除**する |
| 氏名・連絡先等 | アプリに入力する項目が存在しない |
| 診断名・発症時期等 | 研究目的に不要であり、機微性が高いため取得しない |

> **設計上の裏付け：** 生徒の録画ファイルは解析処理の直後にプログラムが削除する実装に
> なっており、録音音声は固定の一時ファイルに保存され毎回上書きされる。
> したがって、**過去の音声・映像は端末上にもサーバー上にも残らない**。

なお、**指導者が登録するお手本の音声・映像は保存される**。これは練習のお手本として繰り返し
再生する必要があるためである。お手本を提供する指導者からは、別途同意を得る。

### 5.5 アンケートの実施

使用期間終了後、アンケートを実施する。これは**本調査の目的②（アプリへのフィードバック
を得る）を果たすための中心的な手段**であり、補足的な調査ではない。

| 項目 | 内容 |
|------|------|
| 実施時期 | 使用期間（約1か月）の終了後 |
| 所要時間 | 5〜10分程度 |
| 形式 | 選択式の設問＋自由記述欄 |
| 内容 **【要確定】** | 使いやすさ／続けやすさ／画面の分かりやすさ／今後も使いたいか／改善要望（自由記述） |
| 配慮 | 聴覚障害のある生徒が対象であるため、**文字と図を中心とした平易な設問**とする。学年・発達段階に応じて表現を調整する |
| 任意性 | 回答は任意であり、無回答による不利益はない |

自由記述で得られたフィードバックは、アプリの改善に活用する。
公表時は、個人が特定されうる記述（氏名・学校名・固有の出来事等）を除いたうえで引用する。

### 5.6 分析の方法

| 対応する目的 | 分析 | 内容 |
|------------|------|------|
| ① 発音の改善 | スコアの推移 | 参加者ごとに、練習回数に対する得点の変化を回帰分析により評価する |
| ① 発音の改善 | 苦手な音の変化 | 音ごとの点数を集計し、初期に低かった音が改善したかを確認する |
| ① 発音の改善 | 属性との関連 | 学年・障害の程度とスコアの推移との関連を検討する（§5.3 の配慮のうえ実施） |
| ② フィードバック | アンケートの集計 | 選択式は単純集計、自由記述は内容ごとに分類して整理する |
| ② フィードバック | 改善要望の整理 | 自由記述から改善要望を抽出し、優先度をつけて今後の開発計画に反映する |
| 両方 | 利用状況 | 練習回数・継続日数を集計し、無理なく使用できたかを確認する |

個人が特定される形での公表は行わず、**集団としての傾向**、または匿名化した個別の推移として
報告する。

## 6. 個人情報およびデータの取扱い

### 6.1 参加者の識別方法と匿名化

参加者はアプリに**利用者 ID とパスワードでログイン**し、練習記録を個人ごとに分離して
保存する。

#### 匿名性を確保するための運用ルール

本人が ID を自由に決められる場合、氏名やあだ名をそのまま入力してしまい、
**データ内に個人が識別できる文字列が残る**おそれがある。これを防ぐため、以下を徹底する。

| ルール | 内容 |
|--------|------|
| ID の形式を指定する | 研究者があらかじめ**参加者番号（例：A01, A02）を割り当て、これを ID とする**。本人が自由入力できる形にしない |
| 本人が決めるのはパスワードのみ | 「自分のアカウント」という感覚を持てるようにしつつ、識別子には個人情報が混入しない |
| 氏名等の入力を禁止 | 画面上に「名前は入れないでください」と明示し、入力欄にも注意書きを表示する |

> **推奨：** ID まで本人に決めさせると匿名化が崩れるリスクが高い。
> **ID は割り当て、パスワードのみ本人が設定する方式**を推奨する。

#### 対応表の管理

- 氏名と参加者番号（ID）の対応表は、**学校の担当教員が保管**し、研究者側には渡さない
  （または、施錠可能な場所に保管し、研究責任者のみが管理する）
- 研究者が取り扱うデータには氏名等の直接的な識別情報を含めない
- パスワードは**暗号化（ハッシュ化）して保存**し、平文では保持しない

> **【要確定】** 対応表の管理者・保管方法は学校側と協議のうえ決定する。

## 7. 倫理的配慮

### 7.1 参加の任意性と撤回の自由

- 参加は完全に任意であり、**参加しないことによる不利益は一切ない**ことを明記する
- 学業成績や学校での評価に一切影響しないことを、生徒と保護者の双方に明確に伝える
- **調査開始後であっても、理由を問わずいつでも中止できる**
- 中止を申し出た場合、その参加者のデータは速やかに削除する（ただし、既に集計・公表された
  分については削除できない旨をあらかじめ説明する）

### 7.2 予測される負担・リスクと対策

| リスク | 内容 | 対策 |
|--------|------|------|
| **心理的負担** | 発音を点数化されることで自信を失う、劣等感を抱く可能性がある | ・点数だけでなく改善点を具体的に示す設計にしている<br>・「前回より上がった点」を強調する表示にしている<br>・担当教員が生徒の様子に配慮し、負担が見られる場合は使用を中止する |
| **身体的負担** | 画面を見続けることによる疲労 | ・1回の練習は1〜2分程度<br>・使用頻度を強制せず、学校の指導計画の範囲内とする |
| **プライバシー** | 音声・映像は個人が特定されうる情報である | ・**生徒の音声・映像は保存しない設計**（§5.4）<br>・アプリに保存されるのはスコアと日時のみ |
| **時間的負担** | 授業時間や自習時間を使用する | ・学校の指導計画に組み込む形とし、追加の負担を生じさせない<br>・アンケートは5〜10分程度、1回のみ |
| **属性情報による特定** | 学校・学年・障害の程度の組み合わせから個人が推測されうる | ・障害の程度を区分に丸める<br>・少数事例を単独で公表しない<br>・詳細は §5.3 |
| **自由記述による特定** | フィードバックの記述内容から個人が推測されうる | ・引用時は固有名詞・個別の出来事を削除する<br>・必要に応じて要約して引用する |

### 7.3 参加者にとっての利益

- 自分の発音の状態を、聴覚に頼らず**視覚的に確認**できる
- 指導者が隣にいない場面でも、自分のペースで反復練習ができる
- 練習の記録が蓄積され、自分の変化を確認できる

ただし、**本アプリの使用により発音が改善することは保証されない**ことを、
説明文書に明記する。

### 7.4 結果の公表

- 研究成果は卒業研究および学会等で発表する可能性がある
- 公表にあたっては個人が特定されない形とする
- **学校名についても、学校側の意向を確認したうえで匿名化の要否を判断する**
